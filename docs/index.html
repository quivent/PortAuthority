🚢 Getting Started

What is Porter?

Porter is a command-line tool that simplifies local development by mapping custom subdomains to your local services. Instead of remembering port numbers, just use clean subdomain names. Porter handles the complexity of hosts file management and URL routing automatically.

  • Map subdomains to ports (e.g., api.localhost:3000)
  • Automatic /etc/hosts file management with backups
  • Open services in browser with one command
  • Persistent configuration across sessions
  • Cross-platform support (macOS, Linux, Windows)
  • Beautiful, colorful terminal output
💡 Pro Tip: Think of Porter as your harbor master - it assigns each service (ship) a friendly name and dock (port), so you never have to remember which port number is which service.

📦 Installation

🔧

Quick Install

Build and install from source:

git clone https://github.com/yourusername/port-authority.git
cd port-authority
cargo install --path .

Quick start:

# Set your base domain
porter set base localhost

# Map a subdomain to a port
porter map api 3000

# Open in browser
porter open api

🧭 Core Concepts

🛟

Understanding Subdomain Mapping

Porter creates a mapping between memorable subdomain names and port numbers. Instead of accessing your API at localhost:3000, you can use api.localhost:3000. Porter manages your hosts file automatically, so these domains work seamlessly.

How It Works

  1. Set Base Domain - Configure your base domain (usually localhost)
  2. Create Mappings - Map subdomains to ports (e.g., api → 3000)
  3. Hosts File Updated - Porter adds entries to /etc/hosts automatically
  4. Access Services - Use clean URLs like http://api.localhost:3000

Example Mappings

Subdomain Port Full URL Typical Use
app 3000 http://app.localhost:3000 Frontend application
api 8080 http://api.localhost:8080 Backend API
admin 4000 http://admin.localhost:4000 Admin dashboard
docs 3001 http://docs.localhost:3001 Documentation site

Hosts File Management

Porter automatically manages entries in your hosts file between special markers:

# BEGIN PORTER MANAGED
127.0.0.1    api.localhost    # porter:port=3000
127.0.0.1    app.localhost    # porter:port=8080
# END PORTER MANAGED

Porter creates automatic backups before making changes, ensuring your hosts file is always safe. All Porter-managed entries are clearly marked and isolated from other system entries.

📋 Command Reference

⚓ Port Management Commands

porter list
Core

Lists all active ports and the processes using them. Your go-to command for seeing what's running in your development harbor.

porter list [OPTIONS]
Options:
--range, -r Specify port range (e.g., 3000-8000)
--filter, -f Filter by process name
--json Output in JSON format
--verbose, -v Show detailed process information

Examples:

# List all active ports
porter list

# List ports in common dev range
porter list --range 3000-8080

# Find all Node.js processes
porter list --filter node

# Get detailed JSON output
porter list --json --verbose
porter check
Core

Check if a specific port is available or in use. Returns detailed information about the occupying process if the port is taken.

porter check <PORT> [OPTIONS]
Options:
--kill, -k Kill the process if port is in use
--wait, -w Wait for port to become available
--timeout Timeout for wait operation (seconds)

Examples:

# Check if port 3000 is available
porter check 3000

# Check and kill if occupied
porter check 8080 --kill

# Wait up to 30 seconds for port to be available
porter check 5000 --wait --timeout 30
porter kill
Requires Elevated Permissions

Terminate the process using a specific port. Use with caution - this is the equivalent of ordering a ship to leave the harbor immediately.

porter kill <PORT> [OPTIONS]
Options:
--force, -f Force kill (SIGKILL instead of SIGTERM)
--all, -a Kill all processes on the port
--yes, -y Skip confirmation prompt

Examples:

# Kill process on port 3000 (with confirmation)
porter kill 3000

# Force kill without confirmation
porter kill 8080 --force --yes

# Kill all processes on port 5000
porter kill 5000 --all
⚠️ Warning: Killing processes can cause data loss or system instability. Always verify what you're killing before proceeding.
porter find

Find an available port within a specified range. Perfect for when you need a free dock for your service.

porter find [OPTIONS]
Options:
--range, -r Port range to search (default: 3000-9000)
--count, -c Number of available ports to find
--sequential Find sequential ports

Examples:

# Find one available port
porter find

# Find port in specific range
porter find --range 8000-9000

# Find 3 sequential available ports
porter find --count 3 --sequential

🗺️ Hosts File Management

porter hosts list

Display all custom hosts file entries. Shows your local DNS mappings.

porter hosts list [OPTIONS]
Options:
--filter, -f Filter entries by hostname or IP
--custom-only Show only custom entries (exclude system)

Examples:

# List all hosts entries
porter hosts list

# Show only .local domains
porter hosts list --filter .local

# Show custom entries only
porter hosts list --custom-only
porter hosts add
Requires Elevated Permissions

Add a new hosts file entry. Maps a hostname to an IP address for local development.

porter hosts add <HOSTNAME> <IP> [OPTIONS]
Options:
--comment, -c Add a comment to the entry
--force, -f Overwrite existing entry

Examples:

# Add a local development domain
porter hosts add myapp.local 127.0.0.1

# Add with comment
porter hosts add api.dev 127.0.0.1 --comment "Local API server"

# Update existing entry
porter hosts add staging.local 192.168.1.100 --force
porter hosts remove
Requires Elevated Permissions

Remove a hosts file entry by hostname.

porter hosts remove <HOSTNAME> [OPTIONS]
Options:
--yes, -y Skip confirmation prompt

Examples:

# Remove a hosts entry
porter hosts remove myapp.local

# Remove without confirmation
porter hosts remove api.dev --yes
porter hosts backup
Optional

Create a backup of your hosts file. Always a good idea before making changes!

porter hosts backup [OPTIONS]
Options:
--path, -p Custom backup location

Examples:

# Create backup with timestamp
porter hosts backup

# Backup to specific location
porter hosts backup --path ~/backups/hosts.backup

📊 Monitoring & Services

porter watch
New

Monitor port activity in real-time. Watch your harbor and see ships come and go.

porter watch [OPTIONS]
Options:
--range, -r Port range to monitor
--interval, -i Refresh interval in seconds (default: 2)
--alert Alert on new port usage

Examples:

# Watch all ports
porter watch

# Monitor development port range
porter watch --range 3000-8080 --interval 1

# Get alerts on changes
porter watch --alert
porter status

Get a comprehensive overview of your development environment status.

porter status [OPTIONS]
Options:
--services Show common service status (DB, Redis, etc.)
--health Perform health checks on services

Examples:

# Get overall status
porter status

# Check service health
porter status --services --health

🚀 Common Workflows

Workflow 1: Starting a New Development Project

When starting a new project, you want to ensure your ports are clear and ready.

# 1. Check if your preferred port is available
porter check 3000

# 2. If occupied, see what's using it
porter list --filter 3000

# 3. Kill the old process if needed
porter kill 3000

# 4. Add a custom hosts entry for your project
sudo porter hosts add myproject.local 127.0.0.1 --comment "My awesome project"

# 5. Start your development server
npm run dev

Workflow 2: Cleaning Up Stuck Ports

When processes don't shut down cleanly and occupy ports.

# 1. List all active ports in dev range
porter list --range 3000-9000

# 2. Identify stuck processes
porter check 8080

# 3. Kill the stuck process
porter kill 8080 --force

# 4. Verify the port is now free
porter check 8080

Workflow 3: Setting Up Multiple Services

When you need to run frontend, backend, and database simultaneously.

# 1. Find three available sequential ports
porter find --count 3 --sequential

# 2. Check the status of common service ports
porter status --services

# 3. Add hosts entries for each service
sudo porter hosts add frontend.local 127.0.0.1
sudo porter hosts add api.local 127.0.0.1
sudo porter hosts add db.local 127.0.0.1

# 4. Monitor all services
porter watch --range 3000-5432 --alert

Workflow 4: Daily Development Routine

Your daily checklist before starting work.

# 1. Get overall environment status
porter status --health

# 2. List active development ports
porter list --range 3000-9000

# 3. Check hosts file entries
porter hosts list --custom-only

# 4. Clean up any orphaned processes
porter list --filter node
# Review and kill as needed

# 5. Start your watch to monitor activity
porter watch --range 3000-8080

🎓 Advanced Topics

Automation with Porter

Integrate Porter into your shell scripts and automation workflows.

Shell Script Example

#!/bin/bash
# setup-dev-env.sh - Automated development environment setup

set -e

# Function to ensure port is available
ensure_port_free() {
    local port=$1
    if porter check $port | grep -q "in use"; then
        echo "Port $port is occupied. Cleaning up..."
        porter kill $port --yes
        sleep 1
    fi
}

# Setup ports
ensure_port_free 3000
ensure_port_free 5000
ensure_port_free 5432

# Add hosts entries
sudo porter hosts add myapp.local 127.0.0.1 --force
sudo porter hosts add api.myapp.local 127.0.0.1 --force

# Start services
echo "Starting frontend on port 3000..."
cd frontend && npm run dev &

echo "Starting backend on port 5000..."
cd ../backend && npm run dev &

# Monitor services
porter watch --range 3000-5432

JSON Output for Programmatic Use

Use Porter's JSON output mode for integration with other tools.

# Get JSON output
porter list --json --range 3000-9000

# Example output:
{
  "ports": [
    {
      "port": 3000,
      "process": {
        "pid": 12345,
        "name": "node",
        "command": "npm run dev",
        "user": "developer"
      },
      "state": "in_use"
    }
  ]
}

# Use with jq for filtering
porter list --json | jq '.ports[] | select(.port == 3000)'

# Count active ports
porter list --json | jq '.ports | length'

Configuration File

Porter can read settings from a configuration file: ~/.porter/config.yaml

# ~/.porter/config.yaml
defaults:
  # Default port range for operations
  port_range: "3000-9000"

  # Default watch interval (seconds)
  watch_interval: 2

  # Enable alerts by default
  enable_alerts: true

# Custom port labels
labels:
  3000: "Frontend Dev Server"
  5000: "Backend API"
  5432: "PostgreSQL"
  6379: "Redis Cache"
  8080: "Proxy Server"

# Service health check endpoints
health_checks:
  - name: "Frontend"
    port: 3000
    path: "/health"
  - name: "API"
    port: 5000
    path: "/api/health"

# Hosts file management
hosts:
  # Automatically backup before changes
  auto_backup: true

  # Backup directory
  backup_dir: "~/.porter/backups"

Control Porter behavior through environment variables.

🔍 Troubleshooting

Common Issues and Solutions

Issue: "Permission denied" when killing processes

Solution:

# Use sudo for elevated permissions
sudo porter kill 3000

# Or if you own the process
porter kill 3000 --force

Issue: Can't modify hosts file

Solution:

# Hosts file operations require sudo
sudo porter hosts add myapp.local 127.0.0.1

# Check hosts file permissions
ls -la /etc/hosts

# Backup hosts file first
sudo porter hosts backup

Issue: Port appears available but can't bind

Solution:

# Check with verbose output
porter check 3000 --verbose

# Look for TIME_WAIT connections
netstat -an | grep 3000

# Wait for port to fully release
porter check 3000 --wait --timeout 60

Issue: Porter command not found

Solution:

# Verify installation
which porter

# Check GOPATH is in PATH
echo $PATH

# Reinstall if needed
go install github.com/yourusername/porter@latest

# Or add GOPATH/bin to PATH
export PATH=$PATH:$(go env GOPATH)/bin
💡 Debug Mode: Run Porter with PORTER_LOG_LEVEL=debug for detailed troubleshooting information: 
PORTER_LOG_LEVEL=debug porter list

❓ Frequently Asked Questions

Is Porter safe to use in production?

Porter is designed primarily for local development environments. While it's safe to use, production environments typically have more sophisticated monitoring and process management solutions (like Kubernetes, systemd, or Docker Swarm) that are better suited for that purpose.

How does Porter compare to lsof or netstat?

Porter is built on top of system tools like lsof and netstat but provides a more developer-friendly interface with additional features like hosts file management, service monitoring, and workflow automation. Think of it as a specialized tool that makes common development tasks easier.

Can I use Porter on Windows?

Yes! Porter works on Windows, macOS, and Linux. On Windows, some commands may require running your terminal as Administrator (similar to using sudo on Unix systems).

Does Porter affect system performance?

Porter has minimal performance impact. Most commands execute quickly and don't run in the background. The porter watch command does run continuously but uses minimal resources (similar to running top or htop).

Can I extend Porter with custom commands?

While Porter doesn't have a plugin system yet, you can easily integrate it into shell scripts and create wrapper functions in your shell profile. Check the Advanced Topics section for examples.

What happens if I accidentally kill an important system process?

Porter shows you process information before killing and asks for confirmation (unless you use --yes). System critical processes usually require elevated permissions to kill. However, always double-check what you're killing - it's good to run porter check <port> first to see what process is using it.

How do I update Porter?

Update Porter using the same method you used to install it: 

# Via go install
go install github.com/yourusername/porter@latest

# Check your version
porter version --check-update
